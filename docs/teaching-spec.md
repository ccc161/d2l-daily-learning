# 每节教学与交付规范

用中文提供每天一节、约 40 分钟的 D2L 课程。默认学习者能阅读基本 Python，深度学习从头开始，示例使用 PyTorch。课程初始为 136 节，完整路线约 4.5 个月。

## 执行顺序

1. 读取本仓库最新 `curriculum.json`、`progress.json` 和学习聊天里的最新反馈。
2. 按 `next_lesson_id` 与 `learning_blocks` 选择下一节。不要每次从第一节开始或只发送提醒。
3. 阅读对应教材与源码，核对依赖；按需链接伯克利 2019 春季课程的讲义、视频和作业。用英文教材编号，中文教材作辅助。
4. 在 `lessons/NNN/` 生成完整学习包并验证，再把学习包、公开进度和必要目录更新一起提交到 GitHub。
5. 在学习聊天中给出可直接阅读的中文笔记、关键代码、作业和每个文件的 GitHub 链接。文件生成完成不等于已推送，要对照实际聊天交付记录。

## 时间安排

10 分钟阅读与回顾、20 分钟代码练习、10 分钟作业与核对。笔记和课件是两种阅读方式，无须重复阅读。安装、下载和长训练耗时另列，核心示例优先 CPU、小数据和少量迭代。超长训练列为选做；确需拆课时保留历史课号并记录总数变化。

## 每节必须交付

- `notes.html`：第 N/总数节、主题、目标、先修要求、时间安排、概念直觉、必要公式与张量形状、例子、常见错误、来源链接、下一节预告。
- `lesson.py` 和 `lesson.ipynb`：可独立运行的代码、中文注释、依赖、运行命令、随机种子和输入输出说明。Notebook 从头执行不依赖隐藏状态。尽可能执行核心示例；如未执行，明确说明原因，不能编造实测结果。
- `homework.txt`：至少一道概念题与一道代码题，合计约 10 分钟，说明输入、验收标准和提示；额外挑战标为选做。
- `answers.html`：逐题对应的参考答案、必要推导、完整代码和典型误区，单独呈现，明确自编或改编。
- `slides.html`：5–7 页可直接浏览并打印的实际课件，含目标、核心概念、图解或形状变化、代码要点、练习与回顾。不要用待办大纲代替成品。
- 必要的实验结果与简短验证记录。确认代码、笔记和答案相互一致，且页面可读。

## 进度与重复运行

分别记录 `delivered`、`confirmed_completed`、作业状态和 `next_lesson_id`。只有学习者明确反馈或交作业才能确认完成；时间经过或成功推送不代表学完。原始个人反馈保留在私有聊天，公开仓库只保留必要的课次状态和结果摘要。

同一 Asia/Taipei 日期已交付时不重复推进。失败后重试同一课次；补跑一次只推一节。没有完成反馈也按计划推送下一节，并列出尚未确认的项目。学习者要求重讲或调整时遵从新要求并保留原进度。

## 定时与课程结束

由 ChatGPT Work 云端任务在每天 20:00 Asia/Taipei 触发，调度状态和认证存于私有任务设置。GitHub 是资料与进度的持久来源，不依赖原 Mac 的路径、开机状态或本地自动化。迁移验证成功前不得宣称云端定时已生效。

课程材料全部交付后，在最后一节给出总结与未完成项目清单，停用该课程的后续触发；不要因此声称学习者已全部完成。
